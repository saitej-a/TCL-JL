# Phase 7.1: Analytics Aggregation & Privacy Suppression Context

## Phase Goal
Implement the core aggregation engine and wait-time calculation service in `apps/analytics/services.py`, strictly enforcing the mandatory `<5` candidate privacy suppression threshold (ANAL-03, ANAL-04). This service layer will power the public overview, batch, stream, and regional analytics endpoints built in Phase 7.2.

## Key Decisions

### D1: Wait-Time Calculation Pipeline (ANAL-03)
- **Primary Transition:** Offer Letter to Joining Letter (`OFFER_LETTER` -> `JOINING_LETTER`).
- **Fallback Transition:** If Offer Letter date is missing for a candidate, fall back to Interview to Joining Letter (`INTERVIEW` -> `JOINING_LETTER`).
- **Data Source Priority:**
  1. `TimelineEvent` records (matching `event_type=OFFER_LETTER` or `INTERVIEW`, and `JOINING_LETTER`).
  2. Fallback to `CandidateProfile` date fields (`offer_letter_date` or `interview_date`) if the corresponding `TimelineEvent` is absent.
- **Metrics Computed:**
  - `average_days` (mean, rounded to 1 decimal or integer)
  - `median_days` (50th percentile)
  - `min_days` and `max_days`
  - `sample_size` (number of candidates contributing to the wait-time metric)

### D2: Privacy Suppression Threshold (ANAL-04)
- **Setting:** `ANALYTICS_MIN_COHORT_SIZE = 5` in `config/settings/base.py` (already present from Phase 4.2).
- **Suppression Strategy:** Full Cohort Suppression.
  - If a queried cohort (or filtered slice) has `total_candidates < ANALYTICS_MIN_COHORT_SIZE`, all breakdown metrics and wait-time statistics are completely suppressed.
  - The response payload returns:
    ```json
    {
      "data_source": "COMMUNITY_REPORTED",
      "suppressed": true,
      "message": "Not enough community data to display this breakdown."
    }
    ```
  - Sub-breakdowns or raw distributions are never zeroed or partially revealed if below threshold to prevent differential inference attacks.

### D3: Architectural Boundary (Read-Only)
- Per 11_AI_AGENT_RULES §7.5 and 09_PROJECT_ARCHITECTURE: `apps/analytics` is strictly read-only and maintains **no persistent write models** or database migrations.
- All aggregations are computed dynamically via Django ORM (`.annotate()`, `.aggregate()`, SQL date arithmetic) on `CandidateProfile` and `TimelineEvent` tables.

### D4: Legal Disclaimer and Data Provenance
- All aggregated outputs must carry `data_source: "COMMUNITY_REPORTED"` and the standard non-affiliation disclaimer:
  *"These figures are based on community-submitted data and are not official TCS statistics."*
