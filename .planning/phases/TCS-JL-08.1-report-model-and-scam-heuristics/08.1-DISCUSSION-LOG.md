## Flagged-content action (scam scanner verdict)

| Option | Description | Selected |
|--------|-------------|----------|
| Hard-block with 400 | Return 400 `scam_pattern_detected` before the row is written; zero scam-exposure window; matches roadmap's "intercepted pre-publication" | ✓ |
| Publish + auto-report | Content publishes instantly and a PENDING SPAM report is auto-created for 8.2 triage (08 §8's second branch); no innocent post denied but real scam briefly live | |
| Hybrid by pattern severity | Hard patterns block with 400; softer ones publish with auto-report; most precise but two behavior paths | |

**User's choice:** Hard-block with 400
**Notes:** Follow-up asked what the 400 should disclose. Options: name the category / fully generic / echo the matched regex. User chose **name the category** — honest users can fix false positives, scammers learn nothing about the actual regexes. The spec's `matched_pattern` return value stays internal-only.

## False-positive handling (pattern source)

| Option | Description | Selected |
|--------|-------------|----------|
| Settings-held, read at call time | Four spec patterns in settings, compiled at call time with invalid-regex guards; tune without deploy (matches 5.1 D1 / 7.2 precedent) | |
| Code constants in heuristics.py | Exactly 08 §8.1's shape — module-level SCAM_PATTERNS; every tweak is a deploy, but spec literal | ✓ |
| Defer admin-editable to 8.2 | Keep 8.1 literal; a later phase makes patterns Admin-editable | |

| Option | Description | Selected |
|--------|-------------|----------|
| Include repetition detection | One extra regex (10+ repeated chars) in the same scanner, same 400 path | |
| Defer | Ship only the four scam patterns (MOD-04's literal scope) | ✓ |

**User's choice:** Code constants (spec-literal); repetition detection deferred
**Notes:** Both choices went against the recommended options — user's deliberate trade: spec fidelity over operational flexibility. The category-naming 400 (Flagged-content action) becomes the primary false-positive mitigation as a consequence. The "admin-editable patterns" idea was redirected to Deferred Ideas (see below) rather than silently folded into 8.2's locked scope.
