<threat_model>
**T-08.1-01 (HIGH): Report flooding / brigading.** An authenticated user submits thousands of reports to bury the queue. Mitigations: `reports` scope at 10/hour wired on the view (not just the class — 7.2 R1), plus the pending-dedup conditional UniqueConstraints at DB level. Verified by: 429 test + IntegrityError→400 mapping test.
**T-08.1-02 (MEDIUM): Report enumeration / data exposure.** The 201 body returns only {id, status, message}; there is no listing endpoint in 8.1; reviewed_by/moderator_notes are staff-only fields never serialized on create. Verified by: response-shape assertion tests.
**T-08.1-03 (LOW): Regex/pattern disclosure via error messages.** Not applicable to this plan (no scanner here), but the envelope discipline is established: error codes are stable strings, messages never embed internal matching data.
</threat_model>
