<threat_model>
**T-08.1-03 (HIGH): Scam regex leakage to attackers.** Echoing `matched_pattern` in HTTP responses
hands scammers the exact evasion recipe. Mitigation: `matched_pattern` is an internal return value;
the response carries only `CATEGORY_MESSAGE` (category-naming, pattern-free). Verified by: response
body assertions in test_heuristics + test_scam_scanner_integration.
**T-08.1-04 (MEDIUM): Debounce-cache poisoning / key collision.** A user-controlled key could
gag another author's posts. Mitigation: author_id is inside every hash input; keys live under the
`moderation:dup:post:` namespace; values store only the author id for diagnostics. Verified by:
per-author isolation tests (two authors, identical content, both succeed).
**T-08.1-05 (MEDIUM): Scanner bypass via edit path.** If only creates were scanned, a clean post
could be edited into a scam. Mitigation: merged-state scanning on both edit paths (D5). Verified by:
merged-state edit tests.
**T-08.1-06 (LOW): False-positive lockout of honest users.** Legitimate content matching the
`guaranteed joining` regex is refused. Accepted trade-off (D7/D8 — user decision): category-naming
400 explains what to change; patterns are deploy-gated. Verified by: benign-sample tests proving
the scanner's precision on representative honest phrasing.
</threat_model>
