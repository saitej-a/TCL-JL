# Phase 8.1 Plan 08.1-02: Scam Heuristics & Duplicate-Post Debounce Summary

**Plan 08.1-02 closed the phase's anti-spam surface: `heuristics.py` scans every post and comment
write through the real HTTP views, blocking scam content with a 400 before any row exists, while
the 60-minute debounce (spec title hash + a body hash) stops identical reposts — all per the
user's discuss-phase decisions D1–D8.**

## Performance

- **Heuristics (MOD-04, D7):** `apps/moderation/heuristics.py` ships 08 §8.1's four `SCAM_PATTERNS`
  verbatim as module-level compiled constants — paid-JL fee solicitation, Telegram/WhatsApp contact
  scams, guaranteed-joining claims, NextStep/Ultimatix credential requests. `evaluate_content_safety(title, body)`
  returns the spec's shape; `matched_pattern` is an internal diagnostic only.
- **Hard-block UX (D1/D2):** matching content is refused with 400 `scam_pattern_detected` carrying
  `CATEGORY_MESSAGE` — it names the category ("possible fee solicitation or credential request") so
  honest users can rephrase, and no response anywhere can contain the regex (asserted by test:
  no pattern source string may appear in the message).
- **All four call sites (D4/D5):** `PostListCreateView.post` (scan → debounce → create → register
  hashes), `PostDetailView.patch` (merged-state scan before save), `CommentListCreateView.post`,
  `CommentDetailView.patch` (merged body scan). A clean post cannot be edited into a scam; proven
  by `test_post_edit_blocked_when_body_becomes_scam`.
- **Debounce (D6, T8.5):** `apps/moderation/debounce.py` stores two MD5 keys per post — the spec's
  `(author_id, title.strip().lower())` plus `(author_id, whitespace-collapsed body)` — through
  Django's cache framework (6.2 D3) with `DUPLICATE_POST_WINDOW = 3600` read at call time.
  Comments are never debounced; edits are never debounced. Author id inside every hash input means
  no cross-author gagging (T-08.1-04). MD5 carries `usedforsecurity=False` (S324) — the spec's own
  non-crypto dedup choice.
- **Gates:** 694 tests pass (638 baseline + 56 new across both plans), `ruff check` +
  `ruff format --check` clean, `makemigrations --check` reports no changes (zero new migrations in
  this plan).

## Decisions Made

- **Scanner guard clauses live in the views, debounce in the view too** (not `services.create_post`):
  the 5.2 defects live in that file area and 8.1 must not entangle with them; views are the
  outermost write gate and see the authenticated user id the debounce keys on. Additive guards only —
  feed filtering, throttles and every pre-existing community test are untouched (694/694 proves it).
- **`_scan_or_raise` helper** centralizes the four call sites' scan-and-translate; comments pass
  `title=""` since the evaluator concatenates title+body per §8.1.
- **Debounce TTL/namespace tests use a spy cache** rather than poking cache-backend internals —
  the suite runs on the real Redis backend, not LocMemCache, so backend-private attributes are
  off-limits.
