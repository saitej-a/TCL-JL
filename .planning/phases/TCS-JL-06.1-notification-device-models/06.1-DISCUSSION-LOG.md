## Message & PII

### Q3: Notification title/message content: stored snapshot or read-time composition?

| Option | Description | Selected |
|--------|-------------|----------|
| Snapshot at creation | Immutable historical record per 07 §3.1/§4.1.1; later deletion can't rewrite what a user was told | ✓ |
| Render at read time | Store only type + FKs; fresh text always, but heavier queries and re-render drift | |

**User's choice:** Snapshot at creation (recommended option taken).
**Notes:** Locked as D3.

### Q4: How does an ANONYMOUS actor appear in the stored message?

| Option | Description | Selected |
|--------|-------------|----------|
| Anonymity-safe label baked in | Service composes via AuthorPublicSerializer semantics ("A candidate" / handle); zero-PII guaranteed once at creation | ✓ |
| Raw recipient-scoped rendering | Store actor id, render per reader; handles rare mode flips but re-opens PII surface per endpoint | |

**User's choice:** Anonymity-safe label baked in (recommended option taken).
**Notes:** Locked as D4 — pairs with 07 §8's zero-PII push rule for 6.2.
