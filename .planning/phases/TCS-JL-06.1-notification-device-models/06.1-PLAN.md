## Planner resolutions (RESEARCH §2 open items 1–8)

- **R1 — Index naming: repo-style, spec columns.** The three compound indexes are named `idx_notif_recipient_read_created` (`recipient, is_read, -created_at`), `idx_notif_recipient_created` (`recipient, -created_at`), and `idx_device_user_active` (`user, is_active`) — the naming convention 4.1/5.1 P3 established, because 07 §3.1–3.2 give columns but no names. Every field-level `db_index=True` from 07 is **kept literally** (`recipient`, `type`, `is_read`, `created_at`, `user`, `is_active`). The single-column indexes on `recipient` and `user` are technically redundant with the compound indexes' leading column; they are retained for literal spec fidelity, documented in the model docstring, and cost nothing at MVP scale. Dropping them was rejected as a silent schema drift; a future phase may prune them with a migration if the index count ever matters.
- **R2 — `CheckConstraint(condition=…)`, not the spec-era `check=`.** Django 5.1 deprecated `CheckConstraint.check` in favour of `.condition` (`RemovedInDjango60Warning`); on the pinned Django 5.2.6 the research's `check=Q(...)` would emit a deprecation warning. The plan pins `condition=Q(is_read=False) | Q(read_at__isnull=False)` and asserts the exact spelling in the migration file.
- **R3 — `Device.__str__` renders no PII.** 07 §3.2 renders `self.user.email`; this plan renders `f"{self.get_device_type_display()} ({self.browser or 'unknown browser'})"` instead. Server-side `__str__` reaches logs, admin lists, and error reports, and 03 §8 already classes tokens (and, by extension, the account identifier behind them) as sensitive. Recorded as a deliberate, documented micro-deviation.
- **R4 — `mark_as_read()` keeps the spec shape, gains a return value.** `def mark_as_read(self) -> bool` — guards on `if not self.is_read`, sets both fields, saves with `update_fields=["is_read", "read_at"]`, returns whether this call flipped the row. 6.2 reports "already read" honestly instead of guessing, and the pair-write rule is enforced in exactly one place.
- **R5 — Everything model-level lives in `models.py`.** No `managers.py` (D6's manager is four lines) and **no `services.py` in 6.1**: 6.2 owns the endpoint-facing services, and D5's application mirror is `clean()` + `mark_as_read()`. This keeps 6.1 free of a module that only 6.2 would exercise. 6.2's `create_notification` contract is recorded under "Out of scope" so the decision is not lost.
- **R6 — `NotificationPreference` is lazily created, explicitly.** No `post_save` signal (import-time signal registration is a test-ordering hazard and would silently create rows for every user); `NotificationPreference.get_or_create_for(user)` is a classmethod and the *only* accessor. Nothing creates a preference row in 6.1 — the test suite asserts that creating a user leaves the table empty, so the laziness is proven, not just intended.
- **R7 — Meta ordering is pinned now.** `Notification.Meta.ordering = ["-created_at"]` and `Device.Meta.ordering = ["-last_seen_at"]`, both with rationale comments, because 6.2's pagination must be stable and the ordering has to match the index/query shape before the endpoints are written. `NotificationPreference` needs none (1:1 read by owner).
- **R8 — CASCADE stays, dormancy is documented.** Per 03's relationship table. `Notification.post` / `Notification.comment` are `null=True, blank=True` so a non-community notification (SYSTEM, TIMELINE_REMINDER, MODERATION) is legitimate, and 03 §12's "explicit nullable foreign keys rather than GenericForeignKey" is honoured verbatim.
- **R9 — `last_seen_at`/`updated_at` are both `auto_now`** (the spec has both). Documented for 6.2: with `update_fields`, `auto_now` fires only for fields included in the update, so 6.2's token-refresh path must include `last_seen_at` explicitly when it wants the refresh timestamp moved.
- **R10 — Test matrix** below (~35 tests; suite 441 → ~476).

## Pinned design — `apps/notifications/models.py`

```python
class Notification(models.Model):
    class NotificationType(models.TextChoices):        # D1/D2 — 07 §3.1 superset
        COMMENT = "COMMENT", "New Comment"
        REPLY = "REPLY", "New Reply"
        VOTE_MILESTONE = "VOTE_MILESTONE", "Upvote Milestone"
        ANNOUNCEMENT = "ANNOUNCEMENT", "Announcement"
        MODERATION = "MODERATION", "Moderation Alert"
        TIMELINE_REMINDER = "TIMELINE_REMINDER", "Timeline Reminder"
        SYSTEM = "SYSTEM", "System Alert"

    id = models.UUIDField(primary_key=True, default=uuid.uuid4, editable=False)
    recipient = models.ForeignKey(settings.AUTH_USER_MODEL, on_delete=models.CASCADE,
                                  related_name="notifications", db_index=True)
    type = models.CharField(max_length=32, choices=NotificationType.choices,
                            default=NotificationType.SYSTEM, db_index=True)
    title = models.CharField(max_length=255)           # D3 snapshot
    message = models.TextField()                       # D3 snapshot
    is_read = models.BooleanField(default=False, db_index=True)
    read_at = models.DateTimeField(null=True, blank=True)
    post = models.ForeignKey("community.Post", on_delete=models.CASCADE, null=True,
                             blank=True, related_name="notifications")
    comment = models.ForeignKey("community.Comment", on_delete=models.CASCADE, null=True,
                                blank=True, related_name="notifications")
    created_at = models.DateTimeField(auto_now_add=True, db_index=True)

    class Meta:
        ordering = ["-created_at"]                     # R7 — 6.2 pagination stability
        indexes = [
            models.Index(fields=["recipient", "is_read", "-created_at"],
                         name="idx_notif_recipient_read_created"),   # unread list + D6 count
            models.Index(fields=["recipient", "-created_at"],
                         name="idx_notif_recipient_created"),        # 6.2 list endpoint
        ]
        constraints = [
            models.CheckConstraint(                     # D5 — first in the project (R2)
                condition=models.Q(is_read=False) | models.Q(read_at__isnull=False),
                name="notification_read_state",
            )
        ]
```

`Notification.clean()` raises `ValidationError({"read_at": [ErrorDetail(..., code="read_state_inconsistent")]})` when `is_read` is falsy while `read_at` is set (the mirror of the constraint, D5). `mark_as_read()` and the manager:

```python
class NotificationManager(models.Manager):
    def unread_count_for(self, user) -> int:
        """D6 seam for 4.2 D1 — walks the (recipient, is_read) prefix of
        idx_notif_recipient_read_created. No order_by (R-5): ordering would
        turn an index-only count into a sort."""
        return self.filter(recipient=user, is_read=False).count()
```

## Scope note (one plan, five tasks — deliberate)

`06.1` is a single roadmap plan (`06-01`) covering T6.1–T6.3, and it is model-only: one new app, one migration, no API surface. All twelve files below are six source files plus six test files inside that one new app, and every task touches at most three source files. No task depends on another plan, so `wave: 1` and `depends_on: []` are the whole dependency graph.
