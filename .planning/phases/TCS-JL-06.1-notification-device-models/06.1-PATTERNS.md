## Analog excerpts

**Model skeleton + named index + rationale comment** (`apps/community/models.py`, Post):

```python
id = models.UUIDField(primary_key=True, default=uuid.uuid4, editable=False)
author = models.ForeignKey(
    settings.AUTH_USER_MODEL,
    on_delete=models.PROTECT,
    related_name="community_posts",
)
...
class Meta:
    verbose_name = "post"
    verbose_name_plural = "posts"
    # Pinned threads first, then newest — 03 §17's (is_pinned, created_at) index
    # is built for this order, and 5.2's pagination depends on it being stable.
    ordering = ["-is_pinned", "-created_at"]
    indexes = [
        models.Index(fields=["category", "created_at"], name="idx_post_category_created"),
        ...
    ]
```

## Conventions to replicate

1. Module docstring: cite spec section numbers + decision IDs (D1–D6) and say why, not just what.
2. Every index/constraint gets an exact name; tests assert them from the migration file **and** prove behavior at the DB layer.
3. Comments carry the cross-reference (`# 07 §3.1`, `# 5.1 D2` style).
4. Tests: `pytestmark = pytest.mark.django_db`; docstring-first test files; intent visible in names.
5. No `str:`-cast settings reads; `django.conf.settings` imported, read at call time.
