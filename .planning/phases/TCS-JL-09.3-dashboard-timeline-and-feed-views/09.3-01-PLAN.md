<objective>
Deliver UI-03 and the content half of UI-01 (roadmap plan 09-03): the candidate dashboard with the
status stepper (§7.4), the interactive personal timeline roadmap (§7.5), and the community feed with
category pills, tabs, debounced search and **optimistic upvoting with automatic rollback** (§7.6) —
plus §7.7's create-post screen, which the roadmap left unassigned and which two feed CTAs target, and
the four backend repairs the phase's own views sit on (D1–D4).

User decisions binding this plan (09.3-CONTEXT.md): D1 (open anonymous read on the community read
surfaces, bound anonymous traffic with a read throttle whose scope is on the view), D2 (fix the
deleted-post feed leak and the vacuous test that hid it), D3 (the vote response gains `has_voted`),
D4 (make community write throttling actually engage), D5 (§7.7 create post ships here), D6 (the
dashboard's discussions block shows newest posts, divergence recorded), D7 (the 12 categories live in
one frontend module because the endpoint stays unbuilt), D8 (Stitch mockups for the four surfaces
before implementation).

Plan-time resolutions (from 09.3-CONTEXT.md's open questions):
- The stepper's source of truth is `GET /timeline/` (every milestone's date is needed), with the
  dashboard payload's `latest_event` as a cross-check; `JOINED` and `JOINING_DATE` both satisfy the
  final §7.4 node, and `OTHER` is never a milestone.
- The §7.5 "automatically update my current status" affordance is **not** a new flag: creating a
  mapped event walks the chain server-side (4.1 D1, proven live by the 9.2 wizard), so the modal
  states that as behaviour and the request carries no client-invented field.
- `ToastProvider` is mounted in `App.tsx` (it is absent from the tree today) so the rollback toast
  in §6.8 has a provider; it wraps the router so page components can call `useToast()`.

Explicitly out of scope: post detail + 1-level comments (§7.8), analytics (§7.9), notification centre
(§7.10), settings (§7.11), reporting UI (§7.12), PWA/service worker (all 9.4); staff UI (9.2 D2);
the `/community/categories/` endpoint and a hiring-stream filter on the feed (D6/D7, recorded).
</objective>

<threat_model>
**T-09.3-01 (MEDIUM): the new anonymous surface is scraped or enumerated.** Opening reads to
visitors exposes community content without credentials. Mitigation: reads stay paginated at 20/page,
the anonymous path is throttled by a bucket proven to engage (Task 2's 429 test), the author payload
is already redaction-safe (`AuthorPublicSerializer` + tombstones), and no write path is added. Verified
by: the read-access test module (anonymous 200 on reads, 401 on every write, throttle engagement).

**T-09.3-02 (MEDIUM): the optimistic pill lies.** A failed vote that leaves the count inflated makes
the UI a false record of the user's own action — the failure mode UI-03 exists to prevent. Mitigation:
state is per card and controlled by the feed (no shared store to desync), the mutation response's
`has_voted`/`vote_count` reconciles on success, failures roll back both count and toggle with a toast,
and the rollback is proven by a real browser observation with the API unreachable (Task 9). Verified
by: UpvotePill unit tests (failure path, 409 path, class assertions) + the live drill.

**T-09.3-03 (LOW): the repaired tests become the defect.** `test_feed_requires_authentication` and
`test_deleted_posts_absent_from_feed` both encode the old, wrong behaviour; updating them without
proving they can fail would leave two more assertions that pass either way. Mitigation: the deleted-post
test asserts by id and is checked by reverting the filter locally; the 401 test becomes a 200 test with
the supersession recorded in its docstring and an explicit 401 assertion kept for writes. Verified by:
Task 3's fail-on-revert check and code review of the diff.

**T-09.3-04 (LOW): write throttling configured so tightly it locks out real users.** Making the write
bucket engage for the first time could produce 429s a user cannot explain. Mitigation: the spec's
30/min rate is unchanged (only the wiring is fixed), the 429 renders as the project's RATE_LIMITED
envelope which the UI surfaces as an inline message, and the engagement test overrides the rate rather
than changing it. Verified by: the engagement test + the live write journey in Task 9.

**T-09.3-05 (LOW): user-authored content rendered as markup.** Post bodies are attacker-controlled
text. Mitigation: React escapes text nodes by default and 9.3 renders bodies as text only — no
`dangerouslySetInnerHTML`, no markdown renderer, no link auto-detection. Verified by: code review of
the card/feed diff plus a test asserting a script-tag body renders as literal text.
</threat_model>
