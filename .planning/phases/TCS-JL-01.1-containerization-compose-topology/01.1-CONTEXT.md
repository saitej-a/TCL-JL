<decisions>
## Implementation Decisions

### Web & Celery bootstrap (placeholder strategy)
- **D-01:** `web` runs a tiny Python stdlib HTTP placeholder responder on :8000 in 1.1 — proves ports, networks, volumes, and healthchecks end-to-end. Entrypoint swaps to gunicorn in Phase 1.2.
- **D-02:** `celery_worker` and `celery_beat` get identical placeholder treatment (heartbeat task / sleep-loop beat schedule). All six services boot clean in 1.1; real tasks arrive with 1.2's Celery app config.

### Nginx & TLS
- **D-03:** Nginx runs in BOTH compose files. Dev: plain HTTP :80 proxying to `web:8000`. Prod: TLS only.
- **D-04:** Prod `nginx.conf` declares TLS 1.3 listeners + HSTS in 1.1, with self-signed placeholder certs under `./nginx/certs/` (mounted by prod compose, cert files gitignored). Phase 10.2 hardening tunes/replaces certs — it does not create TLS from scratch.

### Celery worker layout
- **D-05:** One `celery_worker` service consuming `-Q default,notifications,maintenance`. No per-queue worker split at MVP scale (~2k users); can split later if a queue needs isolation.
- **D-06:** Dev and prod use the identical single-worker/3-queue shape; only env vars and resource limits differ between files. Queue routing map is defined with 1.2's Celery config.

### Version pinning
- **D-07:** Exact minor tags pinned in compose/Dockerfile (e.g. `postgres:16.x-alpine`, `redis:7.x-alpine`, `python:3.11.x-slim` — exact current tags verified at build time). Reproducible; upgrades deliberate. Dependabot/Renovate automation can be added later.
- **D-08:** One shared Dockerfile (python:3.11-slim base, placeholder entrypoint) — same image serves `web`, `celery_worker`, `celery_beat` with different compose commands. 1.2 only swaps entrypoints. No multi-stage builder yet (premature while app is a placeholder).

### Boot order
- **D-09:** Healthcheck-gated chain: `db` healthcheck via `pg_isready`, `redis` via `redis-cli ping`; `web`/`celery_worker`/`celery_beat` use `depends_on: condition: service_healthy`; `nginx` waits on `web` `service_started`. First `docker compose up` must boot clean deterministically (roadmap success criterion 1).

### Volumes & environment
- **D-10:** Named volumes `postgres_data` and `redis_data` (per T1.2 spec). Dev additionally bind-mounts source into `web`/`celery` for hot-reload.
- **D-11:** Single root `.env` consumed via compose `env_file` in dev; prod compose receives real env vars via deployment environment (not files). `.env` is already excluded by T1.1 `.gitignore` rules.

### Claude's Discretion
- Dev DX & git rules detail: Makefile targets (e.g. up/down/logs/migrate), whether branch protection is enforced via GitHub ruleset or repo settings, PR template presence. Constraint: honor T1.1 — `main` requires PR + passing tests; `.gitignore` strictly excludes `.env`, `*.pem`, `serviceAccountKey.json`, `media/`, `node_modules/`.

</decisions>
